# Documentation

Load when creating or editing documentation, specifications, proposals, reports, plans, or guides.

## Required actions

1. Identify the document's purpose, audience, scope, and requested format.
2. Read relevant source material and canonical project docs before stating implementation facts.
3. Preserve correct meaning, constraints, and decisions. Never invent evidence, requirements, or citations.
4. Use the smallest structure that fully serves the purpose. Remove repetition and filler; do not rewrite effective text merely to show activity.
5. State requirements as direct, testable rules. Separate verified facts from recommendations and assumptions.
6. Keep diagrams, tables, examples, and prose consistent with one another.
7. Check links and paths when tools permit. Confirm that code examples are valid or label them illustrative.
8. Deliver the requested artifact without unsolicited appendices or summaries.

## Project style

- Prefer explicit obligations and boundaries over descriptions of mechanisms.
- Use concrete examples and short sentences.
- Put counts and structure before detailed breakdowns when useful.
- Keep one rule per list item or table cell.
- Avoid vague hedging. State real exceptions explicitly.
- Do not delete accurate existing content merely because it was written by someone else; tighten it or explain why it is wrong.
- Review the complete document for accuracy, completeness, consistency, and redundancy before delivery.
