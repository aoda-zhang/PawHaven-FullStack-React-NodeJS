## 1. 动物的一生：完整生命周期概览

### 1.1 核心问题

> 一只流浪动物从被发现到可能被领养，要经历许多阶段。今天，这些阶段高度碎片化——发现动物的人不知道该告诉谁、有能力救助的人根本不知道有这只动物、想领养的人无从信任动物的来历。**链条上每一个断裂的环节，都意味着一只本可以被拯救的动物被放弃了。**

### 1.2 完整生命周期（8 个阶段）

```
  ┌──────────────┐
  │  阶段 0      │  有人发现了一只流浪动物。
  │  发现         │  路人。居民。任何人。
  └──────┬───────┘
         │ 打开 PawHaven，提交上报
         │ （照片 + GPS + 紧急程度）
         ▼
  ┌──────────────┐
  │  阶段 1      │  案例已公开发布。
  │  待响应       │  首页地图/列表可见。
  │  (PENDING)   │  系统通知附近志愿者。
  └──────┬───────┘                            ↑
         │ 志愿者"认领"该案例                    │ 如果 24 小时内无人认领：
         │ （公开声明愿意救助）                  │ 系统逐级扩大通知范围。
         ▼                                     │
  ┌──────────────┐
  │  阶段 2      │  救助者正在前往或
  │  救助中       │  正在执行救助。
  │  (IN_PROGRESS)│  发布更新——照片、文字说明。
  └──────┬───────┘
         │ 动物已安全转移
         │ （诱捕/捕获/运输完成）
         ▼
  ┌──────────────┐
  │  阶段 3      │  初步医疗已完成。
  │  已治疗       │  清洁、包扎、疫苗、
  │  (TREATED)   │  基础体检。
  └──────┬───────┘
         │ 进入恢复期
         ▼
  ┌──────────────┐
  │  阶段 4      │  在救助站或寄养家庭休养。
  │  康复中       │  定期更新康复照片。
  │  (RECOVERING)│  行为评估开始。
  └──────┬───────┘
         │ 康复完成，动物恢复健康
         │
    ┌────┴─────────────────┐
    │                      │
    ▼                      ▼
  ┌──────────────┐   ┌──────────────┐
  │  阶段 5      │   │  终止 X      │  未能存活。
  │  待领养       │   │  救助失败     │  无法救助。
  │  (AWAITING   │   │  (FAILED)    │  逃脱/走失。
  │   ADOPTION)  │   └──────────────┘
  └──────┬───────┘
         │ 领养者申请并通过审核
         ▼
  ┌──────────────┐
  │  阶段 6      │  动物有了永远的家。
  │  已领养       │  领养者发布"到家第一天"。
  │  (ADOPTED)   │  案例归档，完整历史保留。
  └──────────────┘
```

### 1.3 各阶段角色分工一览

| 阶段          | 发现者               | 志愿者（救助者）       | 救助站人员         | 领养者                   | 游客/普通用户       |
| ------------- | -------------------- | ---------------------- | ------------------ | ------------------------ | ------------------- |
| **0. 发现**   | **提交上报**         | —                      | —                  | —                        | 可浏览知识库        |
| **1. 待响应** | 追踪进展，可补充信息 | **认领案例**，询问细节 | 浏览案例，可认领   | —                        | 在地图/列表看到案例 |
| **2. 救助中** | 关注更新             | **执行救助，发布更新** | 可提供运输/协助    | —                        | 查看救助进展        |
| **3. 已治疗** | 关注医疗更新         | **上传医疗记录**       | 提供兽医联系方式   | —                        | 查看医疗时间线      |
| **4. 康复中** | 关注康复             | 发布康复照片           | **确认可领养状态** | —                        | 查看康复照片        |
| **5. 待领养** | 看到案例可领养       | 协助筛选申请人         | **审核领养申请**   | **浏览并申请**           | 查看领养列表        |
| **6. 已领养** | 收到"使命完成"通知   | 被邀请撰写故事         | 案例归档           | **发布到家照片、写故事** | 阅读救助故事        |

> **粗体** = 该阶段的主要行动者。普通人上报后即成为该案例的"发现者"角色。未注册的路人即为"游客"。

## 2. 用户模型：谁能做什么

### 2.1 三级权限（不是三类用户）

PawHaven **不会**让用户在注册时"选择身份"。所有人以同一个 **用户** 身份注册。他们能做什么取决于**权限层级**——逐级递进：

```
  ┌─────────────────────────────────────────────────────────────┐
  │                        游客 (GUEST)                           │
  │  （未登录。通过链接、搜索或首页进入。）                         │
  │                                                             │
  │  可以：                                                      │
  │  • 浏览首页地图/列表中的待救助案例                              │
  │  • 查看任何救助案例详情 + 完整时间线                            │
  │  • 浏览待领养动物列表                                          │
  │  • 阅读知识库文章                                              │
  │  • 阅读救助故事                                                │
  │                                                             │
  │  不可以：                                                    │
  │  • 提交上报（需先注册）                                        │
  │  • 认领案例                                                    │
  │  • 评论、关注或互动                                            │
  │  • 申请领养                                                    │
  └────────────┬────────────────────────────────────────────────┘
               │ 注册（邮箱或社交账号登录）
               ▼
  ┌─────────────────────────────────────────────────────────────┐
  │                     注册用户 (REGISTERED)                     │
  │  （已登录。拥有个人主页。默认层级。）                            │
  │                                                             │
  │  游客的所有权限 + 以下：                                       │
  │                                                             │
  │  • 提交流浪动物上报 → 成为该案例的**发现者**                    │
  │  • 关注任何救助案例 → 收到状态变更通知                          │
  │  • 评论救助案例和故事                                          │
  │  • 给故事和案例点赞                                            │
  │  • 收藏知识文章                                                │
  │  • 申请领养动物（提交申请给救助站）                              │
  │  • 查看个人主页（我的上报、我的关注、我的申请）                  │
  │                                                             │
  │  不可以：                                                    │
  │  • 认领救助案例（需先开通志愿者权限）                            │
  │  • 更新案例状态                                                │
  └────────────┬────────────────────────────────────────────────┘
               │ 自主开通：完善志愿者资料
               │ （设置位置、能力、可出动时间）
               ▼
  ┌─────────────────────────────────────────────────────────────┐
  │                    志愿者 (VOLUNTEER)（注册用户 + 自主开通）   │
  │  （已完成志愿者引导。拥有能力画像。）                            │
  │                                                             │
  │  注册用户的所有权限 + 以下：                                   │
  │                                                             │
  │  • 认领待响应的救助案例                                         │
  │  • 更新案例状态（仅限自己认领的案例）                            │
  │  • 接收附近新案例的推送通知                                     │
  │  • 发布救助进展更新（照片 + 文字）                              │
  │  • 上传医疗记录                                                │
  │  • 请求其他志愿者协助                                          │
  │  • 标记案例为"可领养"                                          │
  │  • 获得志愿者成就和统计数据                                     │
  │  • 接收发现者和领养者的感谢                                     │
  └─────────────────────────────────────────────────────────────┘
```

### 2.2 核心设计原则：角色是流动的，能力是权限决定的

一个用户账号可以**同时**做以上所有事情：

- 小陈是**注册用户**，上报了一只流浪猫（此时她是该案例的**发现者**）
- 小陈也开通了**志愿者**权限，所以她可以认领救助案例
- 小陈后来又**申请领养**一只狗——现在她也是**领养者**

系统按**每个案例**、**每个行为**来追踪角色。没有任何设置页说"我只是一个发现者"。用户就是用户，他们能做什么取决于权限层级。

### 2.3 不同层级在首页看到的内容

| 区域                         | 游客               | 注册用户                | 志愿者                        |
| ---------------------------- | ------------------ | ----------------------- | ----------------------------- |
| **待救助案例地图/列表**      | ✅ 完整浏览        | ✅ 完整浏览             | ✅ 完整浏览 + 距离 + 紧急标签 |
| **"上报流浪动物"入口**       | ✅ 按钮 → 引导登录 | ✅ 可用按钮             | ✅ 可用按钮                   |
| **附近待响应案例（个性化）** | ❌ 无个性化        | ✅ 基于已保存的城市     | ✅ 基于 GPS + 志愿者推送半径  |
| **"你关注的案例"区域**       | ❌                 | ✅ 展示关注的案例       | ✅ 展示关注的案例             |
| **"你认领的案例"快捷入口**   | ❌                 | ❌                      | ✅ 快捷操作面板               |
| **新案例推送通知**           | ❌                 | ❌（关注后可选开启）    | ✅ 附近紧急案例自动通知       |
| **可领养动物**               | ✅ 公开列表        | ✅ 公开 +"申请领养"按钮 | ✅ 同注册用户                 |
| **知识库**                   | ✅ 完整访问        | ✅ 完整 + 收藏          | ✅ 完整 + 收藏                |
| **故事**                     | ✅ 完整访问        | ✅ 完整 + 点赞/评论     | ✅ 同注册用户                 |

## 3. 阶段 0：发现——动物如何被看见

### 3.1 被发现的瞬间

```
                 有人发现了一只流浪动物。
                 可能是任何人。

       ┌─────────┴────────────┐
       │                      │
       ▼                      ▼
  知道 PawHaven？          不知道 PawHaven？
       │                      │
       ▼                      ▼
  打开 App → 上报            搜索"附近流浪动物怎么帮"
       │                     → 通过搜索/社交分享找到 PawHaven
       │                     → 以游客身份进入首页 →
       │                     看到附近已有案例 →
       │                     "哦，我也可以上报！"→
       │                     注册 → 上报
       │                      │
       └──────────┬───────────┘
                  ▼
```

### 3.2 上报向导（6 步）

这是整个产品中最重要的表单。它必须能让一个紧张的、匆忙的、可能单手拿着手机在户外的人顺利完成。

```

┌─────────────────┐ ┌─────────────────┐ ┌─────────────────┐

│ 1-5 张照片。     │ │ 地址显示          │ │ ○ 狗             │
│ 第一张 = 封面。  │ │ （可编辑）。       │ │ ○ 其他：[____]   │
│                 │ │ 地图大头针         │ │                  │
│ [点击拍照]      │ │ 可拖动。           │ │ 数量：[1]       │
│                 │ │                   │ │                  │
│ 必填 ✅          │ │ 必填 ✅            │ │ 必填 ✅          │
└─────────────────┘ └─────────────────┘ └─────────────────┘

第4步：状态评估      第5步：紧急程度判断    第6步：确认
┌─────────────────┐ ┌─────────────────┐ ┌─────────────────┐

│ • 毛色           │ │                  │ │ │ 案例总结     │ │
```

```
  │                                              │
  │         🙏 感谢你的上报！                      │
  │                                              │

  │  X 名志愿者和 Y 个救助站。                     │

  │  ┌──────────────────────────────────────┐    │
  │  │  案例 #PAW-0421 — "受伤的白猫"         │    │

  │  │  上报时间：刚刚                         │    │
  │  └──────────────────────────────────────┘    │
  │                                              │
  │  [📱 追踪此案例的进展]                         │
  │                                              │
  │  等待期间：                                    │
  │  • 📖 推荐阅读："发现受伤动物该怎么办"          │
  │    （来自知识库）                               │
  │  • 🔔 当有人认领此案例时，我们会通知你           │
  │                                              │
  │  想提供更多帮助？[成为志愿者 →]                 │
  │                                              │
  └──────────────────────────────────────────────┘
```

### 3.4 系统在背后做了什么

与此同时，系统自动执行：

1. **创建案例**，写入数据库，状态 = `待响应`
2. **地理编码** → 确定城市、区、大致半径范围
3. **匹配志愿者**，在可配置范围内筛选：
   - 志愿者状态为"在线"
   - 能处理此动物类型（猫/狗/小型动物）
   - 在自己的通知半径设置内
4. **发送推送通知**给匹配的志愿者：
   - 普通紧急："一只流浪猫需要帮助，距离你 2.1 公里"
   - **紧急**：`"🚨 紧急：受伤的猫需要立即救助，距离你 2.1 公里"`（附带紧急提示音）
5. **推送案例到公开首页**地图和列表——**所有人**可见
6. **启动升级计时器**：如果 24 小时内未被认领（紧急案例 2 小时），逐步升级通知范围

## 4. 阶段 1：待响应——等待救助者

### 4.1 所有人看到什么

案例出现在**公开首页**的两种视图中：

**地图视图：**

```
  ┌─────────────────────────────────────────┐
  │     🗺️ 地图（leaflet / Mapbox）          │
  │                                          │
  │          📍 松林路                        │
  │       🐱（紧急）                          │
  │                                          │
  │ 📍 橡树大道          📍 第五大街           │
  │ 🐕                 🐱                    │
  │                                          │
  │ [列表视图] [地图视图]  筛选：▾            │
  └─────────────────────────────────────────┘
```

- 蓝色圆点 = 普通待响应案例
- 红色脉冲圆点 = 紧急待响应案例
- 点击圆点弹出一张小卡片：照片 + 动物类型 + 距离

**列表视图：**

```
  ┌──────────────────────────────────────────┐
  │  待救助案例                               │
  │  ┌──────────────────────────────────────┐ │
  │  │ [照片] 🐱 受伤的白猫                   │ │
  │  │        花园路 · 2.1 公里               │ │
  │  │        🟡 待响应 · 5 分钟前             │ │
  │  │        紧急程度：高 🚨                  │ │
  │  └──────────────────────────────────────┘ │
  │  ┌──────────────────────────────────────┐ │
  │  │ [照片] 🐕 棕色狗狗                     │ │
  │  │        橡树大道 · 3.5 公里             │ │
  │  │        🟡 待响应 · 23 分钟前            │ │
  │  │        紧急程度：普通                   │ │
  │  └──────────────────────────────────────┘ │
  └──────────────────────────────────────────┘
```

### 4.2 发现者看到什么

提交上报后，发现者在两个地方看到此案例：

1. **提交后确认页**（上文已展示）
2. **个人主页 →"我的上报"**——所有上报案例的面板

```
  ┌──────────────────────────────────────────┐
  │  我的上报                                 │
  │                                          │
  │  案例 #PAW-0421                           │
  │  🐱 受伤的白猫                             │
  │  花园路 · 2 小时前上报                      │
  │  状态：🟡 待响应                            │
  │  "我们已通知你附近的 12 名志愿者"            │
  │                                          │
  │  [查看完整时间线]                           │
  │  [补充更多信息]                             │
  └──────────────────────────────────────────┘
```

发现者可以在"待响应"期间随时**补充更多信息**——更多照片、更准确的描述、位置修正。

### 4.3 志愿者看到什么

志愿者收到**推送通知**（如果在推送半径内）：

> `"一只流浪猫需要帮助，花园路附近（距离 2.1 公里）"`

### 4.4 认领机制（核心协作动作）

当志愿者点击**"我来救助这只动物"**：

1. **确认弹窗：**

   ```
   ┌─────────────────────────────────┐
   │  认领"受伤的白猫"？               │
   │                                 │
   │  认领意味着你承诺：               │
   │  • 前往现场                      │
   │  • 尝试救助动物                  │
   │  • 发布状态更新                  │
   │  • 必要时转运至兽医/救助站        │
   │                                 │
   │  [是的，交给我]  [取消]           │
   └─────────────────────────────────┘
   ```

2. **案例状态变更**：`待响应` → `救助中`

3. **所有人看到更新：**
   - 认领者的名字显示在案例上："救助者：李明（志愿者，已救助 12 次）"
   - 其他志愿者看到："已有 1 人处理中"——他们仍可选**协助**
   - 发现者收到通知："李明已认领你的案例，正在前往现场！"

4. **已认领案例在首页分类变化：**
   - 地图：圆点从黄色变为蓝色
   - 列表：从"待响应"标签页移至"救助中"标签页

### 4.5 如果没有人认领会怎样？

**升级时间线：**

| 上报后时间 | 普通紧急             | 紧急                         |
| ---------- | -------------------- | ---------------------------- |
| 0 分钟     | 推送给附近志愿者     | 推送给附近志愿者（紧急提醒） |
| 30 分钟    | —                    | 推送到更大范围               |
| 2 小时     | 推送到更大范围       | 推送给全城志愿者             |
| 24 小时    | 推送给全城志愿者     | 自动升级至合作救助站         |
| 48 小时    | 自动升级至合作救助站 | 平台管理人工介入             |

任何时候，发现者都可以**分享案例链接**到社交媒体上，众筹帮助。

## 5. 阶段 2：救助中——救援进行时

### 5.1 谁能更新状态

**只有认领了该案例的志愿者**（或认领该案例的救助站人员）才能推进状态。

协助志愿者可以发布评论和上传照片，但不能更改状态。

### 5.2 救助者做什么

认领后，救助者需要：

1. **到达现场**（路程时间因情况而异）
2. **发布到达更新**："我已到达花园路。看到第三辆停泊的车底下那只猫。正在准备航空箱。"
3. **执行救助**——可能涉及：
   - 直接捕获（动物亲人，可以直接抱走）
   - 诱捕（需要诱捕笼，可能需要数小时/数天）
   - 与物业管理协调（动物在封闭区域）
   - 呼叫支援（动物有攻击性或体型较大）→"请求协助"按钮
4. **发布救助完成更新**："猫已安全装入航空箱。正在送往爱心宠物医院。"
5. **推进状态**至 `已治疗`

### 5.3 发现者在救助过程中看到什么

发现者通过以下方式追踪救助进展：

1. **推送通知**，每次更新一条：
   - "李明已到达现场"
   - "李明发布了新照片"
   - "猫已安全获救！"

2. **案例时间线**（从个人主页访问）：

```
  ┌──────────────────────────────────────────┐
  │  救助时间线：受伤的白猫                     │
  │                                          │
  │  今天，14:30                              │
  │  🔵 救助中                                 │
  │  猫已安全装入航空箱。正在送往爱心宠物医院。    │
  │  📸 [猫在航空箱里的照片]                    │
  │  ——李明，志愿者                            │
  │                                          │
  │  今天，14:00                              │
  │  🔵 救助中                                 │
  │  我已到达花园路。在公交站旁第三辆车底下       │
  │  找到了那只猫。正在准备航空箱。              │
  │  ——李明，志愿者                            │
  │                                          │
  │  今天，08:15                              │
  │  🟡 待响应                                 │
  │  你提交了此案例。                           │
  └──────────────────────────────────────────┘
```

### 5.4 游客和注册用户看到什么

任何浏览首页的人都可以点击案例，看到相同的时间线——区别是不显示私人联系信息。这种透明度是整个平台**信任的基础**。

## 7. 阶段 4：康复中——恢复期

### 7.1 状态推进触发

初步治疗后，动物被安置在恢复环境中：

- **救助站/机构**——由合作救助站管理
- **寄养家庭**——由志愿者寄养

救助者或救助站人员推进至 `康复中`，并指定：

```

  ○ 寄养家庭：[志愿者姓名]
  ○ 其他：___________

  预计恢复时长：[2 周]
```

### 7.2 持续康复更新

照顾者（救助站人员或寄养志愿者）定期发布更新：

```
  ┌──────────────────────────────────────────┐
  │  康复更新——第 5 天                          │
  │                                          │
  │  "伤口愈合良好。今天已拆线。小白恢复正常      │
  │   进食，被抚摸时会发出咕噜声。安静了很多。"    │
  │                                          │
  │  📸 [猫在休息的照片]                        │
  │                                          │
  │  体重：3.2kg（从 2.8kg 增加）               │
  └──────────────────────────────────────────┘
```

### 7.3 行为评估（领养的关键）

当照顾者认为动物身体恢复后，完成一份**行为评估**：

| 特征               | 评估                                   | 备注 |
| ------------------ | -------------------------------------- | ---- |
| **性格**           | 温顺 / 活泼 / 独立 / 胆小              |      |
| **与人类互动**     | 主动亲近 / 可接受 / 回避               |      |
| **与其他动物**     | 友好 / 无反应 / 有反应 / 未测试        |      |
| **与儿童**         | 适合 / 需注意 / 未测试                 |      |
| **牵引训练**（犬） | 是 / 训练中 / 否                       |      |
| **猫砂训练**（猫） | 是 / 训练中 / 否                       |      |
| **特殊需求**       | 无 / 用药 / 特殊饮食 / 行动辅助 / 其他 |      |
| **领养适配度**     | ✅ 可领养 / ⚠️ 需要更多时间            |      |

这将成为**领养档案**，对领养者可见。

### 7.4 推进至待领养

当满足以下条件：

- 身体康复已确认
- 行为评估已完成
- 疫苗接种到位
- 动物已绝育（或有绝育计划承诺）

→ 照顾者将案例推进至 `待领养`。

## 10. 替代结局：救助失败、重复上报、取消

不是每次救助都以领养告终。系统需要体面地处理非美好结局。

### 10.1 救助失败

救助者在认领后可随时将案例标记为 `救助失败`，原因包括：

- 动物已死亡（现场发现已去世，或治疗过程中去世）
- 在曾经报告的位置找不到动物
- 动物在救助或康复过程中逃脱
- 救助不可行（危险位置、超出安全范围的攻击性行为）

**后续处理：**

- 救助者记录原因（实事求是，不带指责语言）
- 可选择向公众展示或隐藏详细原因
- 案例时间线停在最后活跃的阶段
- 显示尊重的状态提示："此救助未能完成。我们感谢所有尝试帮助的人。"
- 救助者收到情感支持提示，附带相关资源链接
- 允许安慰评论；谴责性评论会被审核过滤

### 10.2 重复上报

如果多人上报了同一只动物，志愿者或管理员可以合并案例：

- 较新的案例标记为 `重复`，并链接到主案例
- 重复上报人收到通知："感谢你的上报！其他人也发现了这只动物——你可以在这里追踪救助进展 [链接]。"

### 10.3 虚假上报/取消

如果案例被判定为无效（虚假信息、动物其实有主人等），管理员可标记为 `取消`，原因仅内部可见。

## 11. 支撑系统

### 11.1 救助知识库

**定位：** 专业策划的教育内容，降低所有人参与救助的门槛。

**出现位置：**

- **上报后推荐**：某人提交上报后，展示相关指南（"发现受伤的猫该怎么办"）
- **志愿者工具箱**：志愿者认领案例时，展示"救助 checklist"和"急救基础"
- **领养教育**：某人申请领养时，展示"新宠到家：前 7 天"
- **独立浏览**：首页可访问的、可搜索的、分类的知识库

**内容分类：**

```
├── 🚨 紧急情况（遇到后立即做什么）
├── 🐱 猫科救助（幼猫护理、TNR、常见疾病）
├── 🐕 犬科救助（安全、犬瘟/细小、大型犬处理）
├── 📋 救助流程（checklist、法律信息、组织联系方式）
├── 🏠 领养与安置（审核、引入新家）
└── 💡 经验分享（资深救助者的心得）
```

**质量控制：** 所有医疗建议必须经过持证兽医审核。文章标注"兽医专业知识"与"社区经验分享"。

### 11.2 志愿者网络与通知引擎

**匹配算法（简化版）：**

1. 新案例创建 → 获取 GPS 坐标
2. 查询志愿者，条件：
   - `volunteer.status = 在线`
   - `distance(案例位置, 志愿者位置) <= 志愿者通知半径`
   - `志愿者擅长类型 IN (案例动物类型, '全部')`
3. 排序依据：距离 + 响应历史 + 经验等级
4. 发送分级推送通知（紧急案例用紧急提醒）
5. 先到先认领——第一个点击"认领"的志愿者获得此案例

**升级规则：**
| 案例紧急度 | 首次通知 | 第一次升级 | 第二次升级 |
|-----------|---------|-----------|-----------|
| 普通 | 5km 半径 | 24h 时扩大至 15km | 48h 时全城 |
| 紧急 | 10km 半径 | 2h 时全城 | 6h 时合作救助站 |

### 11.3 个人主页与成就系统

每个用户的个人主页聚合其所有贡献：

```
个人主页：小陈
├── 📊 我的数据
│   ├── 我上报的案例：3 个（其中 2 个已成功救助）
│   ├── 我参与的救助：8 次
│   ├── 我领养的动物：1 只
│   └── 我写的救助故事：2 篇（48 个赞）
│
├── 🏅 成就（轻量徽章）
│   ├── 🔰 "初次上报"
│   ├── 🔰 "初次救助"
│   ├── ⭐ "救助达人"（参与 10+ 次救助）
│   ├── 📝 "故事大王"（发表 3+ 篇救助故事）
│   └── 💚 "社区英雄"（收到 5+ 封感谢信）
│
├── 📝 动态
│   ├── 我关注的案例
│   ├── 我的案例状态更新
│   └── 已收藏的知识文章
│
└── ⚙️ 设置
    ├── 通知偏好
    ├── 志愿者设置（在线/暂离/关闭、推送半径、动物类型）
    └── 隐私（哪些信息对外公开）
```

成就系统有三个作用：

1. **身份锚定**——"我帮助过 8 只动物"是一个真实的身份
2. **新手引导**——成就引导用户尝试平台的各项功能
3. **信任凭证**——领养者看到"救助达人"徽章会更信任救助者

## 附录：关键设计原则

1. **移动优先**：发现者和志愿者在手机上操作，经常在户外。所有核心流程必须以移动端优先。

2. **逐级权限**：游客 → 注册用户 → 志愿者。没有人被屏蔽信息；操作需要对应权限。

3. **透明度建立信任**：每次状态变更都有时间戳和归属人。完整救助时间线公开可查。这是领养者信任动物来历的原因。

4. **安全第一**：不暴露精确 GPS（仅显示大致区域）。不暴露手机号（仅站内消息沟通）。动物位置在救助完成后自动模糊化。

5. **情感安全**：失败案例受到尊重处理。不允许在评论中使用对发现者或救助者的指责性语言。为救助者提供情感支持资源。

6. **信息真实性**：上报必须附带照片。志愿者认证为可选（降低参与门槛）。医疗记录不可篡改。

7. **一个用户，多种角色**：一个账号可以上报、救助、领养。系统按案例追踪行为，而非按用户设定身份。
