# i18n: how it is maintained and used

> This document covers the **locale structure, the loading model, and the call-site rules**. The
> component inventory and per-key copy live in the package READMEs — not here.

## What I built

`@pawhaven/i18n` is a **private workspace package** that holds one preconfigured `i18next`
instance, three locale folders, and a React `I18nProvider`. The portal wraps its tree in that
provider; every page calls `useTranslation()` and reads `t('key')`.

## Locale structure

Locales are **locale-first, one file per business**:

```
locales/
├── zh-CN/                 (Primary — product targets Chinese market)
│   ├── auth.json          → { "auth": { ... } }
│   ├── carousel.json      → { "carousel": { ... } }
│   ├── common.json        → { "common": { ... } }
│   ├── errorMessage.json  → { "errorMessage": { ... } }
│   ├── footer.json        → { "footer": { ... } }
│   ├── home.json          → { "home": { ... } }
│   ├── imageUpload.json   → { "imageUpload": { ... } }
│   ├── reportAnimal.json  → { "reportAnimal": { ... } }
│   ├── rescueCases.json   → { "rescueCases": { ... } }
│   ├── rescueDetail.json  → { "rescueDetail": { ... } }
│   ├── rescueGuide.json   → { "rescueGuide": { ... } }
│   └── documents/         → Node-only, NOT part of the browser locale
├── en-US/                 (Secondary — same 11 files + documents/)
└── de-DE/                 (Secondary — same 11 files + documents/)
```

### Rules

1. **One business per file.** The filename equals the top-level key, and every file owns a unique
   top-level key. `common.json` is `{ "common": { ... } }`, never `{ "foo": ... }`.
2. **All three locales stay in sync.** Adding a key means adding it to `zh-CN/`, `en-US/` and
   `de-DE/` — including under `documents/`.
3. **Keys are dotted paths** — `t('rescueGuide.steps_title')`, `t('common.cancel')`. There are no
   namespace prefixes at the call site.
4. **Loading stays lazy.** Locale files load as separate chunks on demand; `en-US` is preloaded as
   the fallback locale.
5. **Adding a language** = add one folder with the same 11 files, then register the locale in
   `supportedLngs`.

### `documents/` — Node-only, excluded from the browser bundle

`documents/` holds strings that server-rendered documents need. Each subfolder is one document kind
— today only `pdf/`, which holds shell chrome (`header.json`, `footer.json`) and one file per guide
(`{slug}.json`, the four guide slugs). The Node entry (`@pawhaven/i18n/resources`) reads the folder
from disk with `fs` and builds one key per subfolder.

The browser loader globs `./locales/*/*.json` — **one segment, deliberately**. It matches only files
sitting directly in `locales/<locale>/`, so `documents/` is never bundled or fetched by the browser.
Keep it that way:

- It keeps ~15 KB per locale of PDF copy out of the browser bundle.
- It keeps the "filename === unique top-level key" invariant intact. `documents/pdf/rescueGuide.json`
  and `documents/pdf/footer.json` would collide with the UI files `rescueGuide.json` and
  `footer.json`; the per-locale merge is a shallow `Object.assign` where the later file wins, so
  widening the glob would silently shadow PDF copy with UI keys.

If PDF copy is ever needed in the browser, the lever is this glob, not an i18next namespace.

## Usage (React)

### 1. Wrap the application

```tsx
import { I18nProvider } from '@pawhaven/i18n/i18nProvider';

export function App() {
  return (
    <I18nProvider>
      <YourApp />
    </I18nProvider>
  );
}
```

`I18nProvider` is already mounted in `AppProvider`, above `StoreProvider` and `QueryProvider` — you
do not add it again.

### 2. Use translations

```tsx
import { useTranslation } from 'react-i18next';

const { t } = useTranslation();

t('common.welcome');
t('rescueGuide.steps_title');
t('errorMessage.DATA_VALIDATION_FAILED');
```

### 3. Switch language

```tsx
import { i18n } from '@pawhaven/i18n';

i18n.changeLanguage('en-US'); // supported codes: en-US | zh-CN | de-DE
```

Language persists in `localStorage` under `i18nextLng`, detected on load via
`i18next-browser-languagedetector`.

### Adding a new language

1. Add the language code to `supportedLngs` in `packages/i18n/supportedLngs.js`.
2. Add the locale folder with all 11 files: `locales/fr-BE/common.json`, `auth.json`, etc.
3. Run `pnpm check:i18n` to verify every key the Portal uses exists in all three locales.

## Usage (Node — document / PDF)

`@pawhaven/i18n/resources` is **Node-safe**: it never imports `react`, `react-dom`,
`react-i18next`, `i18next-browser-languagedetector` or `i18next-resources-to-backend`. It reads
`locales/{locale}/documents/` from disk, so PDF copy does not go through the browser loader.

```tsx
import { I18nextProvider } from 'react-i18next';
import { documentI18n } from '@pawhaven/i18n/resources';
import { renderToStaticMarkup } from 'react-dom/server';

renderToStaticMarkup(
  <I18nextProvider i18n={documentI18n}>
    <PdfTemplate locale={locale} />
  </I18nextProvider>,
);
```

Clone the shared instance **per render**, never call `changeLanguage` on it:

```tsx
const instance = documentI18n.cloneInstance({ lng: locale });
```

`documentI18n.changeLanguage(locale)` mutates module state shared by every render in the process.
Two PDFs rendering concurrently in different locales would overwrite each other's language, so each
render clones the instance with its own `lng` (see `pdfBuilder.ts`). Template components read keys
through a `keyPrefix` — e.g. `document.pdf.rescueGuide.*` — not a per-call `lng` option.

## What quality is guaranteed

| Guarantee                            | How                                                                                           | Runs in                                 |
| ------------------------------------ | --------------------------------------------------------------------------------------------- | --------------------------------------- |
| Every used key exists in all locales | `check-i18n` script scans `*.ts`/`*.tsx` for `t(...)` calls and compares against locale files | `pnpm check:i18n`                       |
| Locale files are valid JSON          | `pnpm check:i18n` parses every top-level locale file (`documents/` is skipped)                | `pnpm check:i18n`                       |
| Types                                | `resources.d.ts` declares `documentFallbackLocale` and `documentI18n`                         | declarations only (no typecheck script) |
| Lint                                 | ESLint on `.js`/`.jsx`/`.json`                                                                | `pnpm --filter @pawhaven/i18n lint`     |
